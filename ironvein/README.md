# IronVein

Многопользовательская экономическая RPG для Telegram в дизельпанк-сеттинге альтернативных 1930–1950-х.
Промышленная песочница: добыча → переработка → крафт → транспорт → компании → контракты → рынок.
Цены назначают только игроки. Бот задаёт физику (рецепты, сроки, износ, вместимость, комиссии), но не цены.

К каждому сообщению о действии (добыча, производство, ремонт, рейсы, рынок, контракты, компании, донат)
бот прикладывает пиксельную 2D-сцену (все сцены — `docs/scenes.png`): грузовики с разными кузовами и грузом, поезд с вагонами,
буровая, качалка, плавильня, НПЗ, мастерская, биржа. Экраны статистики (профиль, склады, касса) идут без картинок.

## Быстрый старт

```bash
cp .env.example .env          # впишите BOT_TOKEN от @BotFather и свой Telegram ID в ADMIN_IDS
docker compose up -d --build  # PostgreSQL 16 + бот; миграции применяются при старте
docker compose logs -f bot
```

Тесты в Docker (на PostgreSQL из compose; БД `ironvein_test` создаётся скриптом `docker/initdb`):

```bash
docker compose --profile test run --rm tests
```

Локально без Docker: Python 3.12+, PostgreSQL 16.

```bash
pip install -e ".[dev]"
alembic upgrade head && python -m ironvein.bot
TEST_DATABASE_URL=postgresql+asyncpg://user@127.0.0.1:5432/ironvein_test pytest -q   # БД будет очищена
python -m sim                       # все сценарии экономической симуляции
python -m sim baseline_100 --days 5
```

### Настройки (`.env`)

| Переменная | Смысл |
|---|---|
| `BOT_TOKEN` | токен бота (никогда не коммитится) |
| `TELEGRAM_API_URL` | свой сервер Bot API (Local Bot API Server); пусто — api.telegram.org |
| `DATABASE_URL` | строка SQLAlchemy/asyncpg |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `ENVIRONMENT` | `production` запрещает тестовые выдачи (`/admin_grant`) |
| `GAME_SPEED` | множитель игрового времени (10 = всё в 10 раз быстрее; удобно для альфы) |
| `STARTER_CROWNS`, `MARKET_FEE_BPS`, `CONTRACT_FEE_BPS`, `COMPANY_FEE`, `WAREHOUSE_CAPACITY` | экономические параметры |
| `JOB_POLL_SECONDS`, `PREMIUM_RESERVATION_MINUTES` | фоновые задачи и бронь тиража |

## Команды

`/start` `/profile` `/inventory` `/mine` `/production` `/equipment` `/transport` `/company` `/contracts`
`/market` `/donate` `/help` `/paysupport` `/cancel`. Всё остальное делается inline-кнопками, сообщение
по возможности редактируется, а не дублируется. Для новичка есть экран «Первые шаги».

Интерфейс:
- **Единый терминальный стиль:** заголовки ⟦ РАЗДЕЛ ⟧, моноширинные таблицы, шкалы ▰▱ для запасов, прочности и прогресса.
- **Время показывается реальное**, с учётом `GAME_SPEED`.
- **Ошибка ввода не сбрасывает сценарий:** можно сразу ввести значение заново.
- **Любая команда отменяет незавершённый ввод.**
- **Устаревшая кнопка** даёт понятный ответ, непредвиденная ошибка — сообщение вместо молчания.
- **Непонятный текст** получает подсказку с меню.
- **`/paysupport`** — обращение в поддержку прямо из бота: уходит администраторам и в журнал.

Админ (по `ADMIN_IDS`, каждое действие в `audit_logs`): `/admin` (сводка и проверка инвариантов),
`/admin_user`, `/admin_ban`/`/admin_unban`, `/admin_orders`, `/admin_refund`, `/admin_unlock`,
`/admin_resolve`, `/admin_product`, `/admin_company_owner`, `/admin_active`, `/admin_grant` (только не в production),
`/admin_help`.

## Архитектура

```
ironvein/
  config.py, db.py           Pydantic Settings, async engine
  domain/                    чистые данные и правила без БД
    catalog.py               ресурсы, рецепты, оборудование, модули грузовика, локации, маршруты, месторождения
    premium_catalog.py       товары за Stars
    money.py                 целочисленные комиссии и пропорции
    vehicles.py              характеристики грузовика из модулей, топливо, износ, время в пути
    permissions.py           права в компаниях
  models/                    SQLAlchemy 2 (27 таблиц)
  repositories/              блокирующие запросы к кошелькам и складам
  services/                  вся бизнес-логика (Telegram ничего не знает об экономике)
    ledger.py                двойная запись денег
    stock.py, items.py       склады по локациям и уникальные экземпляры
    production.py            добыча, крафт, ремонт, сборка грузовика
    market.py                ask/bid, частичные сделки, комиссия
    transport.py             рейсы: погрузка → в пути → доставка
    companies.py             компании, роли, касса, активы, закрытие
    contracts.py             поставки и перевозки с эскроу, просрочка, споры
    premium.py               Stars: заказы, тираж, выдача, возвраты
    metrics.py               сверка инвариантов и аналитика
  jobs/runner.py             фоновые задачи: завершение заданий и рейсов, просрочка, брони, возвраты
  handlers/                  aiogram 3: экраны и кнопки
  art/                       генератор пиксельных сцен (Pillow)
  bot.py                     запуск, уведомления
alembic/                     миграции (0001 — вся схема + триггер баланса проводок)
sim/                         экономический симулятор, НЕ подключён к боту и БД
tests/                       интеграционные тесты на PostgreSQL + сквозные тесты бота
```

Redis не используется: состояние текстового ввода (FSM) хранится в памяти процесса. При рестарте теряется
только незавершённый ввод числа; экономическое состояние целиком в PostgreSQL.

### Карта систем и зависимостей

```
месторождения ──добыча──▶ руда / уголь / нефть ──переработка──▶ сталь / дизель / запчасти
     ▲  (общие, истощаются,        │                                   │
     │   регенерация/ч)            ▼                                   ▼
кирка/насос/руки            склады по локациям ◀──── рейсы (грузовик/пешком): топливо, износ, ETA
буровая/качалка (дизель)          │   ▲                       ▲
                                  ▼   │                       │ модули из мастерской
                          рынок ask/bid по локации     контракт перевозки (эскроу)
                                  │                    контракт поставки (эскроу)
                                  ▼
                 кошельки игроков и компаний ── комиссии ──▶ сток (уничтожение)
                 стартовые кроны ◀── эмиссия (единственный источник)
Stars ──▶ премиум-экземпляр ──рынок за кроны──▶ другой игрок (кроны не создаются)
```

### Экономический bootstrap и найденные тупики

Без NPC-магазинов цепочка должна запускаться из ничего. Решения:

| Тупик | Решение (минимальное, без нарушения экономики) |
|---|---|
| Для мастерской нужны запчасти, для запчастей — мастерская | Кустарные рецепты без установки: плавка 4 руды + 3 угля → 1 сталь, ручная выточка 3 стали → 1 запчасть, постройка мастерской из 12 стали руками. Медленно и с потерями, но всегда доступно |
| Кирка сломалась, денег нет — добывать нечем | Добыча голыми руками (2 руды/угля или 1 нефть за смену) → кустарная сталь → новая кирка из 2 стали |
| Дизель только с НПЗ, НПЗ из стали и запчастей | Кустарная перегонка 4 нефти → 1 дизель |
| Нет топлива для первого рейса | Малый «Ржавый колодец» в Ржавой Пади + кустарная перегонка 4 нефти → 1 дизель на месте; пеший перенос до 10 единиц без топлива. Топливо для обратного рейса нужно в пункте назначения |
| Откуда первые кирки | Одна кирка в стартовом наборе, создаётся строго один раз на аккаунт (флаг `starter_granted`, условный UPDATE), с журналом происхождения |

Стартовые кроны — единственная эмиссия. Вывод крон из обращения — комиссии рынка и контрактов, плата
за регистрацию компании.

### Схема БД (основное)

- `accounts` — любой владелец: игрок, компания, системный счёт. Все активы ссылаются на `accounts.id`,
  поэтому учёт личных и корпоративных активов не дублируется. `users` и `companies` расширяют `accounts`.
- `wallets` (main/hold на владельца) + `ledger_tx`/`ledger_entries` — двойная запись. Системные счета
  `system:emission` (баланс отрицательный = вся эмиссия) и `system:fees` (всё уничтоженное).
- `stocks` (владелец × локация × ресурс; free/held) + `stock_movements` — журнал каждого изменения с причиной.
- `items` — уникальные экземпляры (оборудование, модули, грузовики, премиум) со статусом
  idle/busy/loading/in_transit/listed/installed/locked/destroyed, прочностью, серийником, происхождением;
  `ownership_history` — все смены владельца.
- `deposits`, `locations` — мир (засевается из каталога при старте, идемпотентно).
- `jobs` — производственные задания (pending/running/completed/cancelled/failed).
- `market_orders`, `market_trades`.
- `shipments`, `shipment_cargo` — рейсы и груз.
- `companies`, `company_members` (роль + битовая маска прав), `company_invites`.
- `contracts`, `contract_events`, `contract_fulfillments`.
- `premium_products`, `premium_orders`, `payment_events`.
- `operations` — ключи идемпотентности; `audit_logs` — журнал действий с инициатором и счётом, от имени которого действовали.

Рецепты и характеристики лежат в `domain/catalog.py`, а не в таблицах: это данные игрового дизайна под
версионным контролем, и их можно менять без миграций.

### Инварианты и как они обеспечены

| Инвариант | Механизм |
|---|---|
| Баланс и запасы не отрицательные | `CHECK` на `wallets`, `stocks`, `deposits`; проверки в сервисах под `SELECT … FOR UPDATE` |
| Сумма проводок транзакции = 0 | проверка в `ledger.post` + отложенный constraint-триггер PostgreSQL `trg_ledger_balanced` |
| Одна вещь — один владелец/одно состояние | один столбец `owner_id` + единственный `status`; частичные уникальные индексы: одна открытая продажа на вещь, один активный рейс на машину, одна ручная смена на игрока |
| Нельзя исполнить дважды | условные переходы статусов под блокировкой строки; `operations` (одноразовый токен в каждой кнопке); уникальный `telegram_charge_id` |
| Рейс не телепортирует товар | в пути груз списан со склада отправления и есть только в `shipment_cargo`; зачисление в назначении только после ETA |
| Производство и рейсы переживают рестарт | срок хранится в БД; фоновая задача выбирает просроченные и завершает каждый в своей транзакции; повтор — no-op |
| Лимит тиража | `CHECK (issued + reserved <= edition_limit)` под блокировкой строки товара |
| Цена платежа — только с сервера | payload счёта = серверный `public_id`; pre-checkout и оплата сверяются с заказом |
| Резервы = обязательства | `metrics.integrity_report` сверяет hold-кошельки с открытыми bid и контрактами, а held-склады с ask, погрузкой и грузом контрактов (вызывается в тестах и в `/admin`) |
| Тестовые выдачи не в production | `/admin_grant` отказывает при `ENVIRONMENT=production`, пишется в аудит |
| Гонки блокировок | deadlock/serialization (40P01/40001) — транзакция повторяется до 3 раз; ключи идемпотентности исключают двойное выполнение |
| Уведомления не тормозят экономику | отправка — фоновыми задачами; flood control Telegram (RetryAfter) выжидается, не задерживая завершение заданий и рейсов |

Блокировки берутся в одном порядке (кошельки — по id), что исключает взаимоблокировки.

## Правила систем (кратко)

**Добыча.** Голыми руками, ручным инструментом (смена 10 минут, одна на игрока) или машиной (буровая/качалка:
дизель и износ за цикл, до 12 циклов за запуск). Запас месторождения резервируется при старте, а не при
завершении, поэтому конкуренция честная. Регенерация ленивая и детерминированная.

**Производство и износ.** Входы и износ списываются при старте, выход выдаётся ровно один раз.
Отмена возвращает сырьё, но не топливо и не износ. При нулевой прочности установка не работает.
Ремонт машин требует своей мастерской в той же локации, ручной инструмент чинится руками.

**Транспорт.** Три локации: Ржавая Падь (руда, уголь, малый нефтяной колодец), Мазутный Яр (нефть, сланцевый уголь), Котлоград
(торговый узел). Маршруты 60/80/120 км. Грузовик собирается в мастерской из шасси, двигателя Д-4/Д-8/Д-12,
бака и кузова (грузовой/облегчённый/бронированный); модули определяют скорость, грузоподъёмность, расход,
запас хода и прочность. Рейс: погрузка с резервом машины, груза и топлива (можно отменить) → отправление
(топливо сожжено, износ применён, отмена невозможна) → прибытие после ETA. Случайных поломок и нападений нет.
Бронепоезда и караваны в схему ложатся как новые `mode` у `shipments`.

**Рынок.** Ask блокирует товар, bid резервирует кроны. Тейкер выбирает заявку; частичное исполнение для
ресурсов, целиком для уникальных вещей. Комиссия 2% платит продавец, округление вверх на каждой сделке:
дробление не уменьшает комиссию. Самосделки (в том числе со своей компанией) запрещены. Если сделок не было,
бот показывает «—», а не выдуманную цену.

**Компании.** Регистрация за 500 ₭ (плата уничтожается). Роли: владелец/управляющий/сотрудник плюс
переключаемые права (приглашения, вывод денег, рынок, производство, перевозки, оборудование, контракты,
состав). Игрок выбирает, от чьего имени действует. Выплаты переводят существующие кроны. Закрыть компанию
можно только без открытых обязательств: все активы переходят владельцу. Бонусов за факт существования нет.

**Контракты.** Поставка: оплата резервируется при публикации; разрешены частичные поставки с накопительной
пропорциональной оплатой и комиссией (итог совпадает с разовой сделкой); при просрочке поставленное
оплачено, остаток возвращается. Перевозка: заказчик резервирует плату и груз; перевозчик принимает контракт
машиной, и рейс отправляется в той же транзакции (если ETA позже срока, принятие отклоняется); после
серверного прибытия оплата уходит перевозчику. Спор замораживает поставку; администратор с аудитом либо
возвращает остаток резерва, либо возобновляет исполнение. Оплата без поставки невозможна.

**Telegram Stars.** Каталог → карточка → «Оплатить N ⭐» → `sendInvoice` с `currency=XTR` без
`provider_token` → `pre_checkout_query` (ответ одной короткой транзакцией, в пределах 10 секунд) →
`successful_payment` фиксируется отдельной транзакцией, затем выдаётся экземпляр. Если выдача упала, её
доделывает фоновая задача. Лимитированный слот бронируется на время счёта (30 минут); если оплата пришла,
когда выдать нельзя, заказ получает `refund_pending` и автоматически возвращается через `refundStarPayment`.
Возврат после перепродажи блокирует экземпляр у текущего владельца до ручного решения (`/admin_unlock`).
Бот не продаёт за Stars ресурсы, заводы, ускорения и бонусы и не меняет Stars на кроны: кроны за
премиум-предмет приходят только от другого игрока. Рыночный донат даёт косвенное преимущество — это
признано, концентрация капитала видна в `/admin`.

## Утверждённые требования и предварительные числа

Утверждено (ТЗ): отсутствие NPC-рынка и фиксированных цен, игроки задают цены; целые числа для денег;
атомарность, идемпотентность и журналы; транспорт, компании и контракты обязательны; Stars только для
косметики и коллекций, без курса Stars → ₭; русский язык.

Предварительно (гипотезы, все в `domain/catalog.py`, `premium_catalog.py` и `.env`): стартовые 1000 ₭,
комиссии 2%, плата за компанию 500 ₭, рецепты (3 руды + 2 угля → 2 стали и т. д.), стоимость установок,
выходы и износ, характеристики модулей грузовика, расстояния, запасы и регенерация месторождений,
вместимость склада 2000, цены и тиражи в Stars.

## Тесты

`pytest -q` — 210 тестов: интеграционные тесты на настоящем PostgreSQL (схема создаётся миграцией Alembic)
плюс сквозные сценарии через настоящий `Dispatcher` aiogram с подменённой HTTP-сессией. Сквозные тесты
падают, если хоть один обработчик ответил «Сбой терминала».

**Правила Bot API** (`tests/telegram_rules.py`) проверяют каждый исходящий запрос во всех тестах бота так, как
это делает Telegram: корректный HTML только с поддерживаемыми тегами, экранированные `<` и `&`, лимиты
4096/1024/200 символов, `callback_data` до 64 байт, размер клавиатуры, параметры счёта Stars. Отдельный тест
проводит имена с HTML-символами через все экраны, где они видны.

**Настоящий процесс** (`tests/test_e2e_process.py`): запускается `python -m ironvein.bot` против локального
эмулятора Bot API по HTTP. Проверяются long polling, сериализация aiogram, multipart-загрузка PNG и
переиспользование `file_id`, уведомление фоновой задачи, повторное нажатие, полный цикл Stars
(invoice → pre_checkout_query → successful_payment → выдача) и корректная остановка по сигналу без трейсбеков.

**Фаззинг интерфейса** (`tests/test_bot_fuzz.py`): все экраны и действия автоматически извлекаются из кода
и нажимаются с мусорными и граничными аргументами, каждый сценарий текстового ввода получает мусорный
текст. Так найдены и исправлены: падение создания контракта через кнопки, переполнение int64 при поиске
игрока, необработанный разбор устаревших кнопок, «съедание» команд во время ввода.

Покрыто:
однократный стартовый капитал и конкурентная регистрация, отказ БД принять несбалансированную проводку,

## Экономическая симуляция (`python -m sim`)

Агенты используют те же рецепты, выходы, износ, маршруты и характеристики грузовика, что и игра. Цены
рождаются из заявок агентов; NPC-поставок нет. На каждом шаге проверяется сохранение денег и отсутствие
отрицательных запасов. Сценарии: 10/100/1000 игроков, дефицит нефти, монополия стали, нехватка
ликвидности, массовая неактивность, транспортное узкое место, остановка мастерских, концентрация в одной
компании, перепродажа премиума, плюс проверка предлагаемой правки (регенерация ×10).

Результаты (3 игровых дня, текущий каталог):

- **Новичок стартует без NPC.** В Ржавой Пади первая сталь появляется через ~20 минут, мастерская — через ~4 часа.
- **Деньги сохраняются во всех сценариях.** Перепродажа премиума двигает кроны между игроками и не создаёт новых.
- **Выпуск растёт со временем.** При 100 игроках сталь по половинам срока: 12 368 → 16 270, строится 42 грузовика, рейсы идут.
- **Отрасли восстанавливаются.** После нефтяного кризиса дизель растёт с 310 до 751 за половину срока, после остановки мастерских запчасти — со 126 до 3691.
- **Монополия не душит рынок.** Монополист скупает сталь, но выпуск остальных не падает: плавить может каждый.
- **Нехватка ликвидности не останавливает производство.** При стартовых 50 ₭ оно идёт на ручном труде.

### Что изменено по итогам симуляции

Первый прогон на исходных числах показал два узких места:
- уголь Ржавой Пади (50 т/ч на весь мир) кончался за пару часов уже при 100 игроках, и выплавка падала вдвое;
- первый рейс грузовика требовал суточного пешего перехода за дизелем.

Применено:
- регенерация месторождений увеличена в 10 раз, запасы — в 2 раза;
- в Ржавой Пади добавлен малый «Ржавый колодец» (нефть, 800 запаса, +60/ч). Топливо для первого рейса получают кустарной перегонкой на месте. Новых денег и предметов это не создаёт: нефть надо добыть, перегонка идёт 4:1.

Остаётся открытым:
- **1000 игроков на одной карте.** Мастерская у новичка — около 15 часов: при таком масштабе нужны новые локации или месторождения. Схема это допускает.
- **НПЗ в Мазутном Яре за 3 дня не строится**: сталь туда должна прийти рейсами, и поток не успевает сложиться. Это ниша для перевозчиков и контрактов, а не тупик.

Модель упрощённая (поведение агентов эвристическое), её выводы — сигнал для балансировки, а не прогноз.

## Решения, требующие согласования

1. **Вместимость склада** (2000 на владельца в локации) — нужен ли платный апгрейд (ещё один сток крон).
2. **Комиссия контрактов** 2% против рыночной: оставить равными или снизить, чтобы стимулировать контракты.
3. **Реакция на мультиаккаунты.** Сейчас только наблюдение: концентрация, HHI, запрет самосделок через
   свою компанию, журнал всех операций. Полностью предотвратить мультиаккаунты нельзя, мы этого и не утверждаем.
4. **Масштаб мира** для 1000+ игроков: новые локации и месторождения.

## Известные ограничения

- Качество крафта не реализовано: ТЗ допускает его, но не требует.
- Вместимость склада проверяется при старте процессов; выдачу результата переполнение не блокирует (ничего не теряется), но новые поступления блокирует.
- Вес предметов в рейсе упрощён: инструмент — 1, модуль — 5, установка — 10.
- Бот работает через long polling; для webhook нужен отдельный вход.
- В этой среде бот проверен без настоящего токена: сквозные тесты гоняют полный `Dispatcher` с подменённой
  HTTP-сессией. Перед альфой нужна ручная проверка в Telegram, включая реальный платёж Stars и возврат.
